Password hygiene

What makes a password hard to guess

Attackers don't guess at random. They start with leaked-password lists, dictionary words, keyboard walks and personal details, then apply predictable tweaks. A strong password is one those shortcuts can't reach.

Password vs passphrase

Random password

Characters picked by a generator from a large set: letters, digits and symbols.

Best stored in a password manager. Hard to remember, very hard to guess.

Random passphrase

Several words picked at random by a generator, joined with a separator.

Long, and easier to remember and type. Strong only when the words are random.

Two fictional examples, labelled so nobody reuses them:

Example only — do not reuse

walrus-trellis-cobalt-thimble-quarry-nectar

Example only — do not reuse

lagoon.sprocket.hazel.tundra.mosaic

A passphrase is not a quote, song lyric, proverb or famous phrase. Attackers keep lists of those too. Even phrases published as examples of good passphrases end up on guessing lists. Use the generator on the analyzer page and treat anything shown on a screen as already used.

Each random word from a list of W words adds log₂(W) bits. This project's demo list has about 500 words (≈9 bits per word). The EFF Large Wordlist has 7,776 words (≈12.9 bits per word), so six words from it give ≈77 bits.

Entropy, and where it misleads

Entropy measures how many guesses a password would take if it were chosen at random. A simple theoretical estimate:

Entropy ≈ L × log₂(N)

  • L is the password length.
  • N is the size of the character pool: 26 lowercase, +26 uppercase, +10 digits, +33 symbols.

For Password123!: L = 12 and N = 95, so the formula gives about 79 bits, which sounds excellent. But the formula assumes every character was random. This one is a dictionary word, a capital letter at the start, the sequence “123” and a “!” on the end. That is exactly what guessing tools try first.

That's why the analyzer shows two numbers. The theoretical estimate uses the formula above. The pattern-adjusted estimate re-prices each detected pattern at roughly what it costs an attacker who knows the trick. A dictionary word costs about log₂(dictionary size) bits, not 8 × 6.6 bits. Both numbers are estimates. No single formula can measure password strength perfectly.

Why guess-time estimates are only educational

How long a password survives depends on:

  • The attacker model: a targeted attacker who knows your name, or a bulk attacker.
  • Predictability: patterns shrink the effective search space.
  • Hashing algorithm and work factor: Argon2id/bcrypt versus a fast hash.
  • Rate limiting and lockout: these apply to online guessing only.
  • Online or offline: guessing against a login form, or against a stolen hash database.

The analyzer shows several illustrative scenarios side by side to make that point. It does not claim an exact “time to crack”.

10 password security rules

  1. Use unique passwords. One password per account, so a breach at one site doesn't unlock the others.
  2. Prefer long passwords or passphrases. Length multiplies the search space. Aim for 16+ characters, or 5–6 random words.
  3. Avoid predictable information. Names, birth years, pets, teams, companies and colleges are tried first in targeted attacks.
  4. Avoid common passwords. Anything on a “most common passwords” list, or a small tweak of one, falls within seconds.
  5. Never reuse passwords. Credential stuffing replays leaked username/password pairs on other sites automatically.
  6. Use a password manager. It generates and remembers unique, random passwords, so you only memorize one strong passphrase.
  7. Enable MFA. A second factor stops most account takeovers even when the password leaks. Passkeys and security keys also resist phishing.
  8. Never share passwords. Not over chat, email or phone. Legitimate IT and support staff never need your password.
  9. Watch for phishing. A perfect password typed into a fake login page is a stolen password. Check the domain before signing in.
  10. Change a password when compromise is suspected or confirmed. Arbitrary periodic changes tend to produce predictable variants like Summer2025! → Summer2026!.

Why composition rules aren't enough

“Must contain an uppercase letter, a number and a symbol” trains people into one layout: Capitalized word + digits + symbol. Guessing tools know that layout. Modern guidance, such as NIST SP 800-63B, puts length first, allows long passwords and spaces, and blocks known-common passwords. It does not require arbitrary character mixes.

Policy compliance vs strength

A policy is an organization's pass/fail minimum, for example: at least 12 characters, not a common password, no personal information. Strength is an estimate of guessing resistance. “Welcome2026!” may pass an old policy and still be weak. A strong passphrase with spaces may fail a policy that forbids spaces. The analyzer reports the two separately.

How sites should store passwords

A well-built login system never stores your password. It stores a password hash:

password + unique random salt → slow password-hashing function → stored hash

  • Hashing is one-way. The system verifies a login by hashing the typed password with the same salt and comparing. It never needs to “decrypt” anything.
  • Encryption is two-way. Anyone with the key can reverse it, so it's the wrong tool for password storage.
  • A salt makes identical passwords produce different hashes and defeats precomputed tables.
  • Slow, memory-hard functions (Argon2id, scrypt, bcrypt, or PBKDF2 with a high iteration count) make each offline guess expensive. Fast hashes like plain SHA-256 or MD5 are built for speed, which helps attackers here.

See demos/hashing_demo.py in the repository for a runnable Argon2id example that uses a synthetic password only.

Authentication is more than a password

A very strong password still fails against phishing, malware, session theft or a breached site that stored it badly. Real login security is layered:

  • Strong unique password
  • MFA / passkeys
  • Rate limiting
  • Secure password hashing
  • Account lockout & abuse protection
  • Session security
  • Phishing protection
  • Monitoring & alerting
Educational, defensive tool. No passwords are stored, logged or sent to third parties.
